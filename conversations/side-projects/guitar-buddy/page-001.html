Yes. Guitar Pro has several file formats, and the right approach depends on which one you want to target.

Format overview

Format Versions Structure Tooling
.gp3 / .gp4 / .gp5 GP 3–5 Custom binary format (little-endian, length-prefixed strings, header then measures, tracks and beats) Well reverse-engineered. PyGuitarPro (Python) reads and writes all three
.gpx GP 6 Proprietary compressed container ("BCFZ") wrapping an XML score Awkward. Few libraries write it, so I'd avoid it
.gp GP 7 / 8 A ZIP archive containing Content/score.gpif, an XML document, plus some metadata Readable XML. alphaTab (JS/TS) can export it

Practical options

  1. Python + PyGuitarPro, writing GP5. This is the easiest and best-tested route. You build a Song with its tracks, measures, voices, beats and notes, then call guitarpro.write(). GP7/8 and TuxGuitar open GP5 files fine. You get tunings, techniques (bends, slides, hammer-ons, palm mutes), tempo, time signatures, lyrics and so on.
  2. JS/TS + alphaTab. This fits if the tool is web-based. alphaTab can also render and play back tabs in the browser, and it can export .gp (GP7).
  3. Generate the GPIF XML yourself and zip it up as a .gp file. This is possible but the schema is undocumented, so you'd copy the structure of an existing file.
  4. MusicXML as a fallback. Guitar Pro imports it, and it's a well-documented standard, but guitar-specific details (string and fret choices, some techniques) sometimes come through less cleanly.

If the tool is in Python, I'd start with PyGuitarPro writing GP5. Within a few minutes we could have a script that outputs a simple riff, which you'd open in Guitar Pro to confirm the pipeline works before building your actual ideas on it.

That's a good fit for Guitar Pro, because it has built-in chord diagrams. Each chord can carry a name, the fret on every string, a starting fret for the diagram, and optionally which finger to use on each string. Guitar Pro draws the diagram above the staff and plays the chord back so you can hear it. PyGuitarPro can write all of this into a GP5 file.

A simple version of the tool

You'd write each song in a short plain-text file, one line per chord, like this:

title: Autumn Leaves
tuning: standard

Cm7       x3534x    fingers: x21 3 4x
F7        1x122x    fingers: 1x 2 34x
Bbmaj7    x1323x
Ebmaj7    x6878x    fingers: x13 2 4x
Am7b5     5x554x
D7b9      x5454x
Gm6       3x2333

The script turns that into a .gp5 file with one measure per chord. Each measure holds a single strummed whole-note chord with its diagram. Rhythm and timing don't matter here, so the score is just the voicings in order. You'd also get:

  • Chord name above each diagram, exactly as you typed it, including things like C7#9b13
  • Standard notation and tab, so you can see which notes the voicing contains
  • Playback, to check that you transcribed the chord correctly
  • A chord list that Guitar Pro can show at the top of the score, giving you a one-page reference of every voicing in the song

Writing one line per chord is much quicker than drawing diagrams by hand.

Reading the videos for you

You could also paste freeze-frames into this chat. I can often read the fretting hand from a clear screenshot and write the chord line for you. That depends on the camera angle and whether fingers hide the strings, so treat what I produce as a draft to check against the video, not as ground truth. Fully automatic extraction from video is a much bigger project, and I wouldn't start there.

Details to settle

  • Fingers: optional per chord. Left out, the diagram just shows dots.
  • Diagram position: worked out from the highest fret. Voicings above fret 12 need two-digit notation, like x-10-12-11-12-x, and the script can accept that.
  • Tunings and 7-string guitars: easy to support if you need them.

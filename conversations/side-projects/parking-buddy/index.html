#12026-10-11T18:28:44.605Z

I'd like to create an application that addresses the following problem: how to park a given set of cars/vehicles in a garage/barn of a specified size? This turns out to be a somewhat tricky problem once the garage becomes larger than one that will simply accomodate vehicles parked behind their respective doors in one rank. In larger buildings you can angle the vehicles and/or park them behind each other, and so on. When planning a new garage building it's not entirely obvious how many vehciles of what size you can get in, and in what configuration. The arrangement of doors also has an impact on the vehicle payload and how they can be parked. Key to determining where vehicles can park is their turning circle: basically you have to simulate the car driving in through the door then turning with whatever turning radius it has, backing up and so on, all leaving clearance around the walls, door jambs and other vehicles. The idea I have for how to help solve this problem (select the size, door configuration for a proposed garage vs the required vehicle payload) was to make an application that lets you simulate the parking. My vision is that this will be a web application (browser side code only, static hosted on the server) that uses some sort of 2D animation. The user would be able to enter the proposed building size and door arrangement, along with a selection of vehicles (perhaps they can pick from small, medium and large cars as a starting point). Then they could click to run the simulation and the "cars" would drive in the door/doors, turning according to their simulated turning circle and park in the building. It might be necessary to provide a hint from the user as to the requested parking arrangement, otherwise it might be hard to pick the best one. Or perhaps all possible arrangements could be simulated. I'm not sure about that. Anyway, the idea is that by playing around with the variables and running the simulation several times, the user can get an idea how their proposed building would work to accomodate their vehicle collection. Hopefully this makes sense!

I've built a working first version of Parking Buddy. It's a static web app with no dependencies and no build step. Run npm start (or python3 -m http.server 8000) and open http://localhost:8000. It has to be served over HTTP; opening index.html directly won't work.

The 5 automated tests pass, and I tested it in headless Chromium: the animation, the results panel, drag-to-pin, rotating, explore mode and phone width all work with no console errors.

What you get: - Inputs: building size, any number of doors on any wall, obstacles such as posts, and vehicles from five presets (compact car, compact SUV, large SUV, crew-cab pickup, sports car) whose dimensions you can edit. Lengths accept 9'6" as well as decimals. - Rules: clearance while moving, side gap when parked (room to open doors), end gap, driveway apron depth, whether angled parking is allowed, and whether to try to keep every vehicle free to leave. - Simulation: each car drives in from outside a door, turning no tighter than its turning circle and reversing when it needs to. Its path is drawn, with reversing shown dashed. - Results panel: for each vehicle it shows whether it parked, which door it used, how many manoeuvres it took (straight in, 3-point turn, etc.), and whether it can drive out or which car is blocking it.

How I handled the two design questions you raised: - "Best arrangement": the default run parks cars in list order, picking spots that are deep in the building, need a simple manoeuvre, and don't block door lanes or earlier cars' paths. Explore layouts tries many random parking orders and spot choices and keeps the best: most cars parked, then most that can leave freely, then fewest manoeuvres. - User hints: drag any car on the plan to pin it there. Scroll the mouse wheel over it to rotate, or press R to turn it 90°. With auto-run on, the planner re-plans around the pinned cars.

Decisions I made that you might want to change: - Turning model: I use the curb-to-curb turning circle from spec sheets to work out each vehicle's tightest turn. - Mirrors: mirrors are modelled separately from the body, because they're usually what decides whether a car gets through a door. With the default 6-inch clearance, the pickup preset (8 ft across the mirrors) doesn't fit a 9 ft door. I think that's realistic, but it's the kind of result you'll want to sanity-check. - Units: feet only, for now. - 2D only: door heights and anything overhead aren't checked.

Limitations: - Very tight spots: the planner works on a 0.5 ft / 5° grid. With less than about 3 inches to spare, it can miss a manoeuvre that a real driver could make, so treat "doesn't fit" there as "very tight". - Speed: a plan takes 1–3 seconds for 3–5 cars. Explore mode multiplies that by the number of trials; the 5-car barn I tested took about 16 seconds for 12. - Automatic layout: the spot scoring is my own rule of thumb, tuned on a few garage shapes. With the example 3-bay garage it parks each car centred and straight in. In odder buildings the first layout can be poor, which is what Explore layouts and pins are for.

The code is in js/: planner.js does the path search, layout.js picks spots and checks exits, explore.js does the random trials, and main.js and render.js are the UI. The README explains the design. Nothing is committed yet; say if you'd like me to commit it.
